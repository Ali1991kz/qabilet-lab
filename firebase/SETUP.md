# QabiletLab Firebase қосу

Жоба: **qabiletlab**. Web config `web/firebase-config.js` ішінде. Бұл Firebase app-ты анықтайтын ашық баптау, әкімшілік немесе service-account кілті емес. Firebase құпиясөзі клиентте немесе Firestore-да сақталмайды: тек Firebase Authentication-ға жіберіледі. Firebase Auth ID/refresh токендері осы терезенің sessionStorage жадында сақталады; шығу кезінде өшіріледі.

## 1. Authentication

Firebase Console → Authentication → Get started → Sign-in method → Email/Password → Enable → Save.

Енді пайдаланушы логин орнына **email** енгізеді. Құпиясөз кемінде 10 таңба. Аккаунттар Authentication → Users ішінде көрінеді.

## 2. Firestore

Firestore Database → Create database → ID `(default)` → орналасуын таңдаңыз → Production mode.

Firestore → Rules ішіндегі мәтінді репозиторий түбіріндегі `firestore.rules` мазмұнымен толық ауыстырып, Publish басыңыз. Сайттағы `#firebase-setup` бетінде ережелерді көшіру және жүктеу батырмалары бар. Ашық `allow read, write: if true` ережесін қолданбаңыз.

Console: https://console.firebase.google.com/project/qabiletlab/firestore
Authentication: https://console.firebase.google.com/project/qabiletlab/authentication/providers

Firebase CLI-ге өз Google аккаунтыңызбен кірген ортада ережелерді балама жолмен `firebase deploy --only firestore --project qabiletlab` арқылы жариялауға болады. Бұл команда жаңа Google жобасын немесе алғашқы Firestore дерекқорын жасамайды.

## 3. Мұғалім өзі тіркеледі

Сайт → Мұғалім → Тіркелу → аты-жөні, өзі таңдаған логин немесе email, құпиясөз. Сыныпқа қосымша әкімшілік бекіту қажет емес. Жүйе мұғалімге өз сыныбын автоматты жасайды. `teacherAccess` құжатын құрудың қажеті жоқ.

Жай логин 3–32 латын әрпі, сан, нүкте, сызықша, астын сызу таңбасынан тұрады. Firebase Authentication-да жай логин техникалық `<login>@users.qabiletlab.invalid` email идентификаторына сәйкестенеді. Бұл пошта жәшігі емес; сол идентификатор үшін пошта арқылы пароль қалпына келтіру мүмкін емес. Нақты email енгізілген аккаунтты Firebase стандартты email арқылы қалпына келтірумен басқаруға болады. Сайттың өзінде құпиясөзді қалпына келтіру функциясы бұл нұсқада жоқ.

## 4. Мұғалім оқушыларды өзі қосады

1. Өз кабинетінде **Оқушыларды тіркеу** бөлімін ашады.
2. Оқушының аты-жөнін, бірегей логинін және кемінде 10 таңбалы бастапқы құпиясөзін енгізеді.
3. «Оқушыны тіркеу» басады. Ол автоматты түрде осы мұғалімнің сыныбына тіркеледі.
4. Кіру мәліметін оқушыға береді. Мұғалім аккаунты ашық қалады.

Оқушының бастапқы құпиясөзі мұғалім экранында уақытша көрсетіледі; Firestore-да, localStorage-да не экспортталатын жоба ішінде сақталмайды. Құру үшін бөлек уақытша Firebase Auth контексті қолданылады, мұғалімнің токені алмастырылмайды. Бұрыннан бар аккаунтты басқа сыныпқа ауыстыруға жол берілмейді.

Мұғалімнің өзі тіркелуі бүкіл мектепке әкімші құқығын бермейді: тек өз сыныбының жобаларына рұқсат бар. Рөл мен `teacherId` тіркелгеннен кейін клиенттен өзгермейді.

**Маңызды:** бұрын v4.0 ережелерін жариялаған болсаңыз, `firestore.rules` ішіндегі жаңартылған толық ережені Rules-қа қайта қойып Publish басыңыз. Ескі `approvedTeacher` функциясы қолмен бекітуді талап етеді. Қазіргі функция тек өз аккаунты мен өзгермейтін `teacher` рөлін тексереді.

## Жинақтар

| Коллекция | Мазмұны |
| --- | --- |
| `users/{uid}` | Ат, email, рөл, мұғаліммен байланыс, сынып коды |
| `profiles/{uid}` | Мектеп, сынып/пән, қысқа сипаттама |
| `classes/{code}` | Мұғалім ID және көрсетілетін аты |
| `teacherAccess/{uid}` | Бұрынғы нұсқадан қалған; қазір қолданылмайды, клиенттен жазу жабық |
| `work/{uid}` | Жоба JSON-ы, иесінің мұғалімі, нұсқа саны |
| `feedback/{id}` | Пікір, автор, оқушы, мұғалім, рубрика |

Жинақтар алғашқы сәтті жазу кезінде құрылады. Құпиясөз үшін Firestore коллекциясы жасалмайды. Мектеп құпиялық тәртібі бойынша қажет деректі ғана жинаңыз.

## Тексеру жағдайлары

- Өз профилін өзгерту және басқа браузерден қайта кіру.
- Екі мұғалімнің сыныптары бір-бірінің оқушысын көрмеуі.
- Оқушының басқа оқушы жобасын ашуға немесе баға жазуға рұқсаты болмауы.
- Мұғалімнің өзі тіркеліп, тек өз сыныбы мен мониторингін ашуы.
- `teacherAccess` коллекциясына клиенттік жазудың тыйым салынуы.
- Бір жобаны екі терезеден сақтау кезінде ескі нұсқаны басып жазуға тыйым салынуы.
- Ережелерде құпиясөз, рөл және мұғалім байланысын еркін өзгертуге жол болмауы.

Жергілікті mock REST тесттері тіркелу, рөл бекіту, сынып, профиль, жоба нұсқасы, кері байланыс ағынын тексереді. Осы ортада Firebase әкімшілік қосылымы өшірілген; нақты жоба баптауларын өзгерту, тірі аккаунт арқылы толық сынау және Firestore emulator ережелерін орындау жасалмады. Emulator тест пакетін алуға желілік рұқсат болмады. Rules жарияланғаннан кейін жоғарыдағы рұқсат жағдайларын нақты тексеріңіз.

Бұрынғы D1/демо аккаунттар мен жобалар автоматты көшірілмейді және жойылмайды. Firebase-те жаңадан тіркеліңіз; бұрынғы портфолионы қажет болса экспорттап сақтаңыз.
